FIXES
- scripts/run_local.py starts API, UI and durable worker together, requires local DB
  and local private storage, disables external AI, refuses pending migrations, and
  restarts a stopped worker with bounded backoff. --worker-only supports an existing
  local API/UI session. README now recommends this startup path.
- Worker recovers transient DB/network errors with bounded backoff and sanitized
  category-only logging. Per-process heartbeats cannot mark another worker stopped.
- Child processes inherit the resolved database host/name/credentials and media root;
  a missing DATABASE_URL or child launch OSError cannot strand a claimed job forever.
- Duplicate delivery cannot fail a live final attempt. Failed jobs require explicit
  retry. Concurrent retry requests recheck eligibility under the job lock and enqueue
  only one retry; the same saved file/job is reused. Provider caps/ledger are retained.
- New job.phase metadata records scanning, extracting, and final validation/save at
  actual worker boundaries. Status/profile APIs expose processing_stage; completed
  still requires the atomic profile/job commit. Stage updates are attempt-fenced.
- Polling retains 10-second request timeouts, bounded backoff and no-store status reads;
  it pauses in hidden tabs and resumes on visibility. Manual status checks are guarded
  against repeated clicks and retain the delay message when the worker is unavailable.
- Existing card, mountain background, static chips, separate unchecked consent,
  reduced-motion styles, and shared Career Journey are preserved.
