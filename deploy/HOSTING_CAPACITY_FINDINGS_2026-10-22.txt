WHAT IS / IS NOT PROVEN
Proven: small-document parsing fits its memory limit; synthetic restore fits the
reviewed scratch limits; measured scanner baseline conflicts with4GiB/3GiB guard.
Not proven: simultaneous parser+scanner refresh+DB+backup peak under4GiB;
8GB Lightsail end-to-end behavior; current signature update peak; SQS/S3 latency,
malicious/maximum-size files; sustained CPU credits; real jobs/hour or1000 burst SLA.
The two local parser/restore processes overlapped in the Docker VM but shared no
4GiB parent cgroup; that is NOT a4GiB whole-host simulation. Scanner ran separately.
Do not lower backup headroom or remove scanner protection to manufacture a pass.

CAPACITY EXPECTATION
1000 submissions/month averages33/day;1000 at once is not the same workload.
One worker serializes bounded processing. Service capacity must be measured with
full pipeline p95/p99, retries, scan updates and sustained CPU-credit behavior.
1000 files at2MB = ~2GB new originals/month; at12months up to24GB before versions,
replacement cleanup and recovery copies. File bytes are not DB bytes.
Existing DB reference9.72MiB leaves30.28MiB to40MiB review threshold (~31KiB per
additional profile at1000); actual extracted text/index/job growth must be measured.
No claim of1000-user capacity is made from1000 synthetic table rows.

TRADEOFFS AND SAFEST CONDITIONAL MIGRATION
4GB: nominal budget fit, currently rejected as drop-in due backup headroom; not
worth compromising malware scanning/data protection.8GB: plausible capacity
candidate, not validated, exceeds budget before ancillary services. Both remain
single-host outage risks and require credential/recovery redesign.
No migration recommended under the current strict40 ceiling without new evidence.
If management approves further evaluation/budget, first resolve a supported
temporary-credential method for Lightsail S3/SQS/SNS; existing EC2 role/IMDS and
hard-pinned backup instance guards do not automatically transfer. No embedded keys.
Then separately approve an isolated full-stack benchmark with exact scanner image,
fresh signatures and updates, realistic max-size resumes, protected backup overlap,
CPU-credit/queue saturation and recovery. Preserve safeguards; stop on failed guards.
Only after tests and full tax-inclusive costing: approve temporary parallel host
and overlap cost, encrypted backup+isolated verification, intake pause/job drain,
single-writer migration, object/queue mapping and controls, private smoke tests,
DNS/TLS cutover, read-only retained source and later approved retirement. Keep the
existing production-cutover plan intact until an alternative is explicitly approved.
Rollback cannot reactivate stale source DB after new writes without reconciliation;
never maintain two active workers against shared jobs or restore an old DB casually.
No data/queue/region move or new credentials/resources have been authorized.
