Required API contract (local source and focused tests)
- POST hiring/enquiries/: multipart; company, full_name, work_email, kind plus
  kind-specific fields and optional attachments; returns 201 with id/detail.
  Used by company hire/team/drive/founding/leadership forms.
- POST support/employee-transition/: multipart; company/contact, phone, role,
  people_impacted, last_working_day, consent, support details, optional list;
  returns 201 with id/detail. Work-email and consent validation required.
- POST opportunities/applications/: verified active candidate session; JSON
  opportunity_id and optional note; returns 201 id/detail, or 200 on duplicate.
  The approved For Candidates link opens /opportunities, so its production 404
  is directly relevant. All 30 frontend opportunity IDs have backend choices.
- POST careers/applications/: multipart name/email/phone/linkedin/motivation/
  resume; returns 201 id/detail. Reachable through the shared footer Careers
  link, so its production 404 affects required public navigation.
- Candidate entry requires auth/csrf, signup, login, me, logout, verify-email,
  resend-verification and password-reset request/confirm APIs; the talent-network
  flow also uses candidate/profile, candidate/resumes and processing/status,
  resume review/download and legal-document/consent APIs already present locally.
- Careers files are scanned and privately stored for admin review; they do not
  enter candidate-profile resume processing. Opportunity applications attach to
  an existing candidate and do not themselves upload a resume.
